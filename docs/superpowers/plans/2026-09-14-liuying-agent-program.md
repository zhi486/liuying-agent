# 流萤 Agent 化工程计划书

日期：2026-09-14。状态：总体设计已确认；用户授权编写计划并开始开发。本文不是全部功能已交付的声明。

## 1. 目标与现状

**目标：** 将流萤从“接到事件后生成一句话的跑步 chatbot”，升级为覆盖跑前、跑中、跑后的运动 Agent：能理解任务、选择受控工具、利用知识与经授权的记忆、执行有限循环、说明结果来源，并在网络或预算不可用时安全停止。

**架构：** 手机保管原始运动数据和确定性安全控制；云端处理最小化摘要上的有界任务。原生层持久化任务与消息，React 首页负责输入、查看进展、确认和取消，不持有供应商密钥。云端原型采用独立 TypeScript 核心，目标适配 Cloudflare Workers Free / D1；未通过鉴权、费用和隐私验收前不部署。

**技术栈：** 保留 Android Kotlin / Room / OkHttp / Coroutines、React / TypeScript / 现有 Native Bridge；新增无运行时第三方依赖的 TypeScript Agent 核心。首批不复用旧 Python 演示后端作为生产 Agent。

**设计依据：** [已确认设计](../specs/2026-09-14-liuying-agent-design.md)。当前用户指示优先于历史计划。

| 能力 | 开工时真实状态 | 本工程补齐内容 |
| --- | --- | --- |
| 跑步、B5、流萤语音 | 已有实测与回归基础 | 保持隔离，逐阶段回归 |
| 无广告练后总结、5 秒曲线 | 已实现，存在尚未提交的工作 | 提供只读摘要接口，不上传曲线原始点 |
| 首页与四 Tab | 已有界面；发送未接入 | 真实任务、对话、状态、取消与恢复 |
| DeepSeek / Fish | 已有手机直连鼓励及语音 | 与 Agent 职责分开，再接入统一额度 |
| ReAct / Agent Loop | 尚无生产实现 | 有限模型—工具—观察循环 |
| 长期记忆、双 RAG | 已确认方向，未落地 | 分阶段实现、单独验收 |
| 月费用控制 | 没有货币预算账本 | 并发安全预留、结算、熔断和对账 |

“8 / 15 秒语音预算”是等待时长，不是美元额度。角色声音正确也不意味着已经具备 Agent 能力。

## 2. 产品完成后的使用方式

1. **跑前：** 首页输入“结合最近几次跑步，安排今晚轻松跑”。流萤申请必要摘要权限，检索授权记录和资料，提出可修改计划。保存目标或更改警戒设置必须由用户确认。
2. **跑中：** 手机继续采集、连接手环和发出本地确定性提示。允许的低频事件可触发在线陪伴；暂停、结束、取消或内容过期后不再播报旧任务。断网时仍只有内置流萤，不启用系统 TTS。
3. **跑后：** 总结页可发起复盘，流萤引用本次与授权历史摘要解释变化；用户可追问，并选择是否记住明确偏好。没有可靠证据的训练效果或医学结论不编造。

首页展示最近真实任务和输入框，跑步页在独立 Tab；冷启动应落在 Agent 首页，运动进行中始终可返回活动跑步。任务界面展示“正在读取本次摘要”等行动记录，不展示模型内部思考链。

## 3. 系统分工与数据流

```text
React 首页 / 练后总结
        │ Native Bridge：提交立即返回 taskId；查询 / 取消 / 确认
        ▼
Android Agent 任务仓库（独立 Room 数据库）
        │ 鉴权 + 明确授权 + 最小化摘要 + 幂等键
        ▼
云端任务服务 ── 事务预算账本
        │ 最多 3 次模型调用、白名单工具、超时/取消
        ├── 授权跑步摘要（不含原始 GPS 和连续心率）
        ├── 长期记忆（来源、修订、候选确认）
        └── Health RAG / Firefly Lore RAG（分库、引用）
        ▼
结构化答复 / 待确认提案 → 手机任务记录与可选语音

手机传感器 → 本地规则 → 内置流萤警报：不经过云端 Agent
```

### 数据与权限约束

- 默认不上传原始轨迹、连续心率、BLE 原始帧、精确位置。授权摘要也是敏感数据，不能称为匿名数据。
- 用户自由输入也可能包含敏感信息，须在云处理说明中明确；不承诺自动消除自由文本里的地点或隐私。
- 授权范围由已认证的应用服务构造，模型不能自己增大范围；身份认证与摘要授权是两道独立检查。
- 第一阶段工具仅 `runs.list`、`runs.summary`，读当前授权快照，不提供任意 SQL、HTTP、文件系统或手机控制。
- 心率阈值、跑步目标、设置变更及删除记忆采用“提案—展示差异—用户确认—原生校验—执行”；旧提案在状态变化后失效。
- 密钥只在原生私密入口或云端秘密配置中管理。不进入网页包、任务消息、普通日志、Git 或记忆仓库。
- 工具结果、RAG 文档、用户附件均为数据，不能赋予模型新权限。权限检查在程序中执行，不依赖提示词自律。

## 4. Agent Loop 与任务协议

任务对外状态：`queued → running → completed / failed / cancelled / timed_out / blocked`；需要写操作的后续阶段增加 `awaiting_confirmation`。数据库是状态来源，页面刷新不新建重复任务。

- 每任务最多 3 次模型请求，每次输出受 token 上限约束；工具总量上限 6，名称和参数严格校验。
- 模型输出只接受“最终答复”或“结构化工具调用”；未知字段、未知工具、越权 ID、重复调用均停止执行，不猜测修复后重试。
- 模型请求、工具观察与最终答复共同构成下一轮上下文。工具调用不是字符串匹配假装 Agent。
- 任务截止时间覆盖排队与执行。首批核心计时从核心接单开始；手机/云端队列接通时传入剩余时限，不能每层重置。
- 取消立即停止后续步骤并传递 AbortSignal；已经发出的供应商请求可能继续计费，保留费用预留，不承诺撤销外部计费。
- 每次模型调用先预留额度。未知计费状态不能当作零消费；服务端接口还须执行认证用户级并发限制与幂等去重。
- Bridge 现有 Promise 超时为 10 秒，所以 `agent.submit` 只负责落库与返回 ID，不能阻塞等待完整云端回复。前端超时不是远端任务取消。
- 生产状态只表达已有证据：已配置、正在连接、最近成功、鉴权失败、弱网超时、预算不足分别显示，不以“已填密钥”冒充在线。

## 5. 长期记忆与双 RAG

### 长期记忆

记录类型：明确偏好、训练摘要、待确认候选。最小字段包括 ID、用户归属、内容、来源任务/记录、创建与更新时间、版本、确认状态、删除状态。用户可以查看、更正、删除；候选推断不能成为已确认事实。

先实现可管理的结构化记忆，不先做全量聊天向量化。删除必须覆盖检索索引/缓存引用，备份保留期另行告知；不能承诺未设计的“瞬间从所有备份清除”。

### Health RAG

只收录选定官方运动健康材料及用户明确添加的资料，提供来源与适用范围。检索材料用于解释与一般建议，不绕开本地安全规则、不诊断、不从截图反推医学结论。

### Firefly Lore RAG

收录《崩坏：星穹铁道》官方流萤角色、剧情和活动资料；按日增量检查。展示资料版本、发布时间（如来源可得）、最近抓取与最近成功更新时间；更新失败保留旧版本并标注，不谎称实时。提供剧透范围选择。角色资料不进入健康决策依据。

首版采用精选小语料、文本检索和可审计分段，评测证明不足后才引入嵌入；不为“有 RAG”而自动增加付费向量服务。抓取遵守来源规则，不绕过登录或访问限制。撤回、冲突、过期、提示注入、无依据回答均列为测试样例。

## 6. 免费优先与每月 $2 边界

目标覆盖 DeepSeek、Fish、嵌入、检索、存储和知识更新，不只是新 Agent 的文字请求。

### 已核实信息（2026-09-14，仅用于规划）

- Workers Free 每日 100,000 请求、每次 10 ms CPU；付费套餐最低 $5/月，因此本方案不自动升级。[Cloudflare 官方价格](https://developers.cloudflare.com/workers/platform/pricing/)
- D1 Free 每日读取 500 万行、写入 10 万行、总存储 5 GB；免费限额用尽可能使查询失败，必须有降级状态。[D1 官方价格](https://developers.cloudflare.com/d1/platform/pricing/)
- DeepSeek 当前价格页列出的 `deepseek-flash` 支持工具调用，按高峰、输入未命中缓存保守计价为每百万输入 token $0.30、输出 $1.20。接入前重新核验模型兼容性与价格，不能直接假定现有手机端模型已迁移。[DeepSeek 官方价格](https://api-docs.deepseek.com/quick_start/pricing)
- Fish 当前账户计价、剩余额度与可设置硬上限尚未核实；不在本文编造其价格，也不承诺已能保证全 App $2 封顶。

### 实施策略

1. 金额使用整数微美元；请求前保守预留，事务处理并发请求，结束按用量结算。未返回用量、取消、异常和迟到请求保留预留待对账。
2. 初始停止阈值拟设 $1.80，剩余 $0.20 为安全余量，不是供应商账单保证。费率未知、预留不足、账本不可用时停止相应付费请求。
3. 单独记录模型、Fish、检索/更新等类别，显示本月已结算与仍预留费用。免费额度不重复算作可花现金。
4. **现有手机直连 DeepSeek/Fish 不受新云端账本控制。** 对全部入口实施统一授权/预留前，只能声称“新 Agent 请求有预算门禁”，不能声称“全 App 已封顶”。
5. 验证免费层 CPU、存储、认证、定时更新额度及可用性；超额停机而非升级。若免费层无法满足，优先降级更新频率/服务范围，需用户决定后才改架构或预算。
6. 最终确认供应商硬上限能力和账单延迟。没有硬上限的外部服务仍有残余风险，须明确告知，必要时关闭在线语音。

## 8. 测试与发布门禁

- **核心：** 脚本模型仅在测试中使用；验证至少一轮真实工具选择→执行→观察→答复路径，以及 3 次请求/6 次工具的硬上限。
- **持久化：** 任务幂等、崩溃恢复、状态迁移、取消和权限版本；不把 UI 内存数组当持久任务。
- **安全：** 服务端鉴权、用户隔离、摘要权限、严格参数、脱敏错误、RAG 提示注入、令牌不进日志。
- **成本：** 并发预留、费率未知、供应商报错/迟到、结算失败、跨月对账；真实账单与估算分开。
- **前端：** 加载/错误/空态、键盘与小屏、来源与确认、活动跑步返回。不开启假在线或假任务演示冒充生产。
- **回归：** 现有 Android 单测/构建、前端检查、Room/Bridge 仪器测试，涉及语音/BLE 时再做真机；不重复消耗 Fish 测试额度。
- **回滚：** Agent 功能独立开关，可停止云端任务而保持本地跑步与内置流萤；数据库变更采用版本迁移，禁止破坏性重建。
- **上线前才需要的用户操作：** 原生或服务秘密入口填写新密钥、云端账号/认证配置、选择摘要授权范围、批准真实网络联调及真机测试。无需在聊天中发密钥。

## 9. 本轮工作包与后续细化

立即执行 [M1A 核心实施计划](2026-09-14-agent-core.md)。第一批只新增隔离核心与测试，不改 BLE、GPS、心率规则或生产语音。后续每个里程碑开始前补充具体协议、迁移和验收计划，避免现在为尚未验证的云服务写大量投机代码。
