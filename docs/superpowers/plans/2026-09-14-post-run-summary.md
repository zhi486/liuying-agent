# 跑后总结第一批实施计划

**目标：** 从已保存记录读取概要与分段，呈现无广告总结。
**设计：** ../specs/2026-09-14-post-run-summary-design.md
**架构：** Kotlin 只读详情查询经现有 Bridge 返回 React；分段图使用 CSS，与表格共享数据，不增加依赖。沿用用户指定直接实施。

## 任务与验收

- [ ] 命令契约：`history.detail` 接收非空、至多 128 字符且无首尾空白的 `sessionId`；前后端拒绝额外字段。先验证当前 Codec 拒绝合法新命令，再增加校验分支。
- [ ] 本地详情：新建 `coordinator/HistoryDetailQuery.kt`，由 `AppCoordinator` 调用 `repository.getSessionWithSplits`；仅允许 FINISHED，非法 ID、未找到、读取失败返回现有结构化错误，取消异常继续抛出。测试真实概要和分段、缺失值、非完成记录及异常。
- [ ] 前端详情：`features/history/RunDetailPage.tsx`、独立 CSS 与测试；新增 Zod 结果校验和请求类型。异步响应需匹配当前 ID，卸载/切页不污染下一页。
- [ ] 入口：列表记录链接到详情，结束页仅在保存成功且存在 session ID 后增加总结入口。保留既有查看记录按钮。
- [ ] 验证：前端 `pnpm check` 和 `verify:bundle`，原生 `:app:testDebugUnitTest` 与 `:app:assembleDebug`；检查 360px 页面。不自动安装、提交或推送。

连续心率、地图、AI 复盘不在本批；空值不归零，分段图不称实时曲线，旧版命令不支持时提示更新。

## 执行结果（2026-09-14）

上述五项代码与本地验证已完成。第一轮测试确认旧 Codec 拒绝详情命令、旧路由不能呈现总结；实现后修正记录链接断言、测试格式和重复数值选择器。

- 新增只读 `history.detail`，由独立查询函数返回已完成记录，不向前端返回 GPS。6 项原生专项测试覆盖空值、无分段、非法参数、未完成、不存在、读取异常和取消。
- 分段距离在原模型中是累计值；新契约明确命名 `endDistanceMeters`，UI 显示「公里点」，不误称单段长度。
- 详情页、两个入口和错误/迟到响应处理完成；详情 5 项测试及保存入口回归通过。
- 完整前端 127 项、原生 745 项测试通过（失败、错误、跳过均为 0）；APK 构建成功。bundle 初始 JS gzip 96,822 字节，总资源 364,935 字节。
- 本机 Edge 检查 320/360/390px × 浅色/深色六种组合，无横向溢出。测试 Bridge 不连接手机，截图明确标注测试数据，保存在 `docs/handoffs/ui-preview-2026-09-14/summary-*.png`。
