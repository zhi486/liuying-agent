## S1 维护设计

复用 `createCloudTasks().purge()` 与 `recoverFreeExecutions()`，不新增公开管理 HTTP 路由或 DO。`scheduled` 只执行数据库维护，不调用服务工厂、模型、tokenizer 或读取模型密钥/当前费率。

1. 先做已有三条清理 SQL：超时收敛、过期结果正文清空、过期指纹清空。保留去重墓碑、账户、设备和账本，不删除记录。结果到期隐藏仍由现有读路径保障，不等待 Cron。
2. 从新增单行 `agent_maintenance_state` 读取账务游标和版本。每次仅恢复一页、固定最多 5 条，不循环翻页；最坏恢复 41 SQL，加清理 3、读游标 1、写游标 1，共 46 条。
3. 成功后以版本条件更新游标；到页尾才重置为空，下次从头扫描。失败不推进。并发/重叠触发可重复做幂等维护，但旧版本不能覆盖新游标；不引入后台执行租约或模型重试队列。
4. 收据按原费率快照结算；未派发可证明的 prepared 才释放；无收据的 may_have_dispatched 保留 uncertain。永久未知费用不能挡住后页，损坏账务导致失败则保留游标并报告失败，不擅自跳过或退款。
5. 日志只含静态事件名、处理计数和游标提交布尔，不输出游标、任务/设备 ID、正文、原始异常或凭据。异常以静态错误失败，让将来平台事件可见；本轮不配置外部告警或自动通知。
6. 根 Wrangler 明确 `crons: []`，公网/preview 关闭、原本地 D1 占位不变。本轮只有本地手动 scheduled 测试；未来先做维护路径独立云 CPU/D1 读写验证，再考虑每 15 分钟一次，不能套用业务入口的 7 ms 结果。

46 是查询条数边界，不是行扫描、CPU、费用或清除时延保证。既有 purge 为全表条件更新；长期数据增长后需按实测补行级分页。Cron 停止时物理正文清理会延迟，不能据“查询不可见”声称物理数据已清除。

## S2 配置与费率

- `DEEPSEEK_API_KEY` 只由用户在正式目标的私密配置渠道提供，不复用聊天中公开过的密钥，不复制手机已有配置或云验收 session。
- 现有 `RATE_CARD_JSON` 为严格六字段，有效区间最长 24 小时；它是可信管理者核验的快照，不会自动获取价格或续期。本期采用人工核验后更新：更简单，但不保证无人维护时全天可执行。
- 到期拒绝新任务，旧键查询/取消/撤回/收据恢复不依赖新费率；禁止仅把旧价格时间戳向后移。需要无人值守更新时另设计可信来源和变更审核，不让大模型填价格。
- 2026-09-17 官方页的 Flash 峰值 cache-miss 输入／输出为每百万 token 0.30／1.20 美元，作为当日核验事实，不生成长期有效配置。现有双费率会按保守输入上界记账，不伪装为包含缓存/离峰折扣的供应商精确账单。上线前重查模型别名对应版本、锁定 tokenizer 适用性和真实 usage。
- 真实设备凭据沿用随机 Bearer＋D1 摘要，90 天、可撤销；不要开放公开注册。发放/换机/撤销必须是独立可信管理操作，不能让普通 Bearer 自行增额或签发。

## 手机恢复关键路径

S3 已实现独立 `agent_cloud_intents` 表与 AgentDatabase 1→2 增量迁移。双 UUID、完整身份、纯文本和 `prompt_only_v1` 授权快照不可覆盖；一次 `submissionAttempted` CAS、取消/撤回待控制状态持久化。S4 新增固定 HTTPS 六路由客户端、独立 Keystore 凭据库、`agent_cloud_receipts` 与 2→3 增量迁移、结果恢复／确认；1→3、2→3 均经实库验证。详情见各批交接。尚无在线 Bridge／首页接线，也没有真实云凭据。

用户确认在线执行 → Room 原子保存专用 UUIDv4 和不可变授权/身份快照 → 一次 POST 提交 → 以请求键/云 ID 查询 → 结果事务落入 Room → acknowledge。

- POST 响应丢失只查询原键；404 不自动重发或生成新键，提示用户决定新意图。输入/身份变化不能默默借旧意图继续。
- 取消/撤回先保存本机待控制意图，恢复时重试幂等控制；本机隐藏不等于云端已取消，费用未知不当免费。
- acknowledge 失败可重试，不得在 Room 写入前确认。服务器无任务列表，首页列表继续来自本机索引。
- 凭据由原生 Android Keystore 保护，固定 HTTPS origin、禁跟随重定向；不进入 Web 存储、Bridge 普通消息、URL 或日志。
- 首版前台进入/用户恢复时查询已有未决意图，无需立即增加 WorkManager；不得扫描旧 blocked 作为发网队列。
