# M1C-2 个人设备授权与云任务恢复设计

日期：2026-09-14；验收更新：2026-09-15。分类：架构性扩展。用户已确认“仅本人使用、支持撤销和换机、不开放注册；断线恢复查询，不自动重跑已可能扣费的任务”，随后确认本书面规格，包括 90 天凭据与 24 小时结果策略。**M1C-2A 已完成离线库与独立复审；未部署，M1C-2B 未接通。**

## 1. 目标与切片

为现有 `agent-server` 增加可信设备身份和持久云任务状态，使以后手机能安全提交、查询、取消一次明确授权的 Agent 执行。保留 M1A 核心、M1B 本机任务和 M1C-1 模型/预算模块，不改变跑步、BLE、GPS、健康警报与语音。

分三批交付，不能用基础模块验收冒充全部接通：

| 切片 | 内容 | 验收边界 |
| --- | --- | --- |
| M1C-2A，本次实施范围 | 设备凭据校验/撤销、身份隔离、云任务数据库、幂等接单、唯一执行认领、取消/终态/结果恢复与清理规则 | 离线真实 SQL 与安全契约测试；无 HTTP 公开入口、无模型派发 |
| M1C-2B，接续批次 | 应用服务将任务认领、每步授权检查、取消、核心 Loop 与已有账本串起来 | 真实模块组合、假供应商联调；故障后不重跑 |
| M1C 后续上线门禁 | 精确 tokenizer、实际 Workers 类型/远程 D1/免费层验证、私密配置、HTTPS 接口和原生在线任务协议 | 用户另行配合配置、批准小额联调和部署/安装 |

M1C-2A 不增加运行时第三方依赖，不改 Android/React，不创建云资源，不读取真实密钥；主代理实现、子代理只读审查。沿用当前工作树，不提交或推送。

## 2. 方案选择

采用**个人设备凭据＋服务端身份记录**。相比立即建设公开账号系统，它不需要注册、密码重置或邮件流程；相比直接依赖 Cloudflare Access 的应用身份配置，它能在现有 D1 账户与预算之间形成可离线验证的统一归属。未来可替换认证入口，但不为尚未要求的多用户产品预建系统。

这是 bearer 凭据授权，不是不可复制的硬件绑定。设备 ID 是管理标识；任何取得有效凭据的人都可能冒用，需要保护原生私密存储并支持撤销。不能宣传“只有这台硬件能使用”。

## 3. 设备授权

### 身份与凭据

- 首版只有一个由可信管理流程预置的 owner，沿用 `agent_budget_accounts.owner_id`。可以给自己的设备分别发放凭据，所有设备共享同一账户和预算，换机不重置额度。
- owner、device ID 由服务端记录决定，客户端 body 中不得声明或覆盖。现有 Android 的 `ownerId = local`、taskId、clientRequestId、Bridge commandId/helloId 均不是云认证凭据。
- 凭据使用密码学随机源生成 32 字节，外部格式为 `lyd_` 加 64 个小写十六进制字符。这里只使用随机不透明凭据，不自建 JWT 签名/刷新协议。
- D1 仅存完整凭据的 SHA-256 摘要，不保存原值。明文只在可信发放流程中一次性交给操作者，不能写到测试产物、控制台、错误、任务记录或 Git。
- 初始凭据有效期 90 天；可信管理操作可提前撤销。更新/换机发放新凭据并显式撤销旧凭据，不因为“新机登录”就悄悄改变旧机状态。首版不做自动续期。
- 原生私密配置和 Android Keystore 保护在手机接入批次实现；不能把凭据放入 React 状态持久化、Web 存储、页面 URL 或 Bridge 普通消息。

### 管理与普通调用分开

- 不开放注册、公开配对、用户自行发令牌或调整额度的接口。
- 发放、撤销、换机属于可信私密管理边界；普通设备凭据不能调用这些管理操作。未来管理入口必须有独立授权，隐藏路径不算认证。
- M1C-2A 只提供供可信代码组合的库函数及离线测试。不存在未经保护的管理 HTTP 路由，也不会现在生成或展示真实设备凭据。
- 未来普通请求只接受 HTTPS 的 `Authorization: Bearer ...`；不接受 query/cookie/body 里的替代凭据，不做静默容错或跨来源转发。

### 校验与撤销

- 每次业务调用校验形状、摘要、owner/device 归属、失效时间和撤销状态。格式错误、未知、过期和撤销统一视为未认证；数据库不可用是服务不可用，绝不退回旧授权缓存。
- 后续 M1C-2B 在每次模型步骤前还必须检查任务仍运行、原设备仍有效、该任务授权未撤回。原凭据到期或撤销后，不能借新设备凭据继续旧执行。
- 撤销事务将指定设备置为 revoked，并取消它发起的非终态任务；其他设备和已结束任务不受牵连。重复撤销幂等。
- 授权检查与远程 HTTP 派发不是跨系统原子事务。以最后一次成功派发门禁为步骤边界；已通过门禁的在途步骤可能继续。不能承诺撤销瞬间停止所有远程计算或费用。

## 4. 云提交意图、摘要与幂等

只有用户明确点击新的在线执行入口并同意本次云处理，原生层才建立新的云提交意图。既有“保存任务”不会自动变成在线执行，也不能扫描旧 blocked 任务作为待发队列。

在线意图须在原生事务中保存：本机 taskId、专用云 clientRequestId、选定身份绑定、授权快照及提交状态。云 clientRequestId 为新的 UUIDv4，不能在页面刷新时重新生成，也不能用 Bridge commandId 充当持久去重键。

服务端只接受严格任务内容：prompt、cloudProcessing=true、runSummaries 布尔和最多 20 条授权摘要；沿用现有 `parseTask` 的长度、数值及精确字段验证。原生提供的摘要是经本次选择上传的数据，不是服务器已拥有的可任意查询数据库。模型只能读取该快照。

服务端为任务生成独立 cloudTaskId，用于预算的 `cloudTaskId:1..3`；本机关联 ID 和请求键都不授予权限。云端查询、取消、结果确认均以已认证 owner 限定，别人的 ID 与不存在的 ID 对外同为未找到。

### 去重规则

- 唯一键为 `(owner_id, client_request_id)`，不是仅设备或仅正文。不同设备归同一 owner 时不能重复领取执行权。
- 在服务内对规范化后的完整提交内容计算 SHA-256 指纹：prompt 使用当前 trim 规则，摘要按提交顺序及固定字段顺序序列化，包含本机关联 ID 和授权布尔；不使用客户端给出的指纹。
- 同键同内容返回现有任务；同键不同内容拒绝冲突。指纹已到期清除后，同键请求返回“旧请求已结束/过期”，永不当成新的执行。
- 不按正文全局去重。用户主动新建意图使用新键，可以请求同样内容；这属于新任务，必须重新授权和预留费用。
- 每个 owner 同时最多一个 queued/running 任务，使用数据库约束和条件更新，不能靠进程内锁。取消前已发出的远程计算可能尚未结束，因此不将此描述为物理网络并发绝对为一。
- 接单和查询本身不调用模型。接单结果是否已返回给手机，不决定数据库中的任务是否存在。

## 5. 状态、认领与中断

可信服务接单时生成绝对截止时间 `acceptedAt + 30 秒`；重试、查询、换机和执行认领不得重置。M1C-2B 把剩余时间传给核心，排队消耗必须扣除。

| 状态/事件 | 规则 |
| --- | --- |
| queued | 意图已持久化但尚未认领；不表示模型已发送 |
| queued → running | 条件更新原子认领一次；返回私密随机 executionToken，所有后续执行写入必须匹配 |
| running → completed / failed / blocked / timed_out | 仅当前执行权能提交合法结果，且不能覆盖取消或已经写入的终态 |
| queued/running → cancelled | 用户取消、设备撤销或本次授权撤回；事务落库，即使执行器还在等待网络也不能复活 |
| 超过原截止时间 | 仍未结束的任务转 timed_out/deadline；不重新排队、不重新认领 |
| 重复终态写入 | 相同结果幂等；不同结果拒绝冲突；迟到取消/结果不得任意覆盖先落库的终态 |

executionToken 只给可信执行代码，数据库仅存它的 SHA-256 摘要，不能返回给手机或日志。认领后不设计自动租约接管；即使 Worker 退出，也不能让另一实例从第一轮重新执行。若后台任务没有启动或没有完成，下次查询/接单时按原截止时间收敛；是否真正崩溃不能靠“当前进程找不到任务”猜测。

取消以数据库先落库的状态为准。已经 completed 的任务不会因迟到 cancel 改成“从未完成”；已经 cancelled 的任务不会被晚到答案改成 completed。撤回资料权限还须清除尚可查询的结果内容，不能只停止未来步骤。

## 6. 输入与结果保留

这是用户已确认的保留策略，不是当前已发生的数据上传：

- **不在 D1 任务表单独保存 prompt 和运动摘要字段，它们只供当前请求/执行使用。** 不持久化模型中间上下文或工具观察；服务进程丢失后不自动重跑。最终答复可能复述输入中的信息，不能承诺云数据库绝不会出现相同内容。手机仍是原始记录和完整历史的来源。
- 生成的最终答复和对外行动摘要可在云端暂存，供手机断线后取回。答复最多 4,000 字符，行动最多 9 条，必须验证实际结构；不存内部推理、原始响应和供应商错误正文。
- **结果自终态写入起最长可查询 24 小时，或手机确认已成功写入本机 Room 后立即清除内容，以先到者为准。** 查询本身不是确认。确认请求幂等；客户端不得在真正落库前提前确认。
- 接单指纹在接单 24 小时后清除；保留 owner、云/客户端任务 ID、状态、时间等不含正文的最小幂等记录，防止旧请求再次执行。不保存任务标题，因为标题可能就是用户输入。
- 到期读取必须立即隐藏内容，不能等清理任务碰巧跑到；M1C-2A 实现并验证清理 SQL，实际定时清理和失败告警是上线门禁。不承诺云备份瞬时清除或无限期恢复结果。
- 短暂保存的答复也可能含健康信息；摘要指纹也不宣称匿名。设备撤销阻止旧凭据读取，新设备须经同一 owner 的可信发放流程获得权限。

## 7. 模块与存储职责

预计新增文件（仅在方案确认后的实施计划中展开代码）：

- `agent-server/src/device-auth.ts`：凭据生成/摘要、可信发放与撤销、实时校验、绑定身份。普通校验与私密管理函数分开，不接受网页自报 owner。
- `agent-server/src/cloud-task-contracts.ts`：独立云任务 DTO、严格输入/结果/状态校验与静态脱敏错误；不挤入 M1A 的模型内部错误枚举。
- `agent-server/src/cloud-tasks.ts`：D1 幂等接单、归属查询、唯一认领、终态提交、取消、授权撤回、确认和到期清理。撤回取消非终态任务，并清除该任务的尚存结果；已完成状态仍保留。对外操作必须重新验证当前主体，执行操作使用绑定的执行权并检查原设备。
- `agent-server/migrations/0002_agent_device_tasks.sql`：新增设备和云任务表，不改写原预算历史；已有 0001 数据迁移后可继续读取。
- `agent-server/test/device-auth.test.ts`、`test/cloud-tasks.test.ts`：真实 Web Crypto 与真实 SQLite 验证，凭据全为测试生成。测试宿主加载两次迁移，不用业务结果假实现替代 SQL。

设备表保存 device_id、owner_id、token_hash、created/expires/revoked 时间。云任务表保存 cloud_task_id、owner_id、创建设备、client_request_id、payload_digest、state/reason、accepted/deadline/updated 时间、execution_token_hash、合法最终结果及清理时间。所有外键、状态组合和唯一性由迁移约束保证；精确列与接口在实施计划中一次性定稿。

## 8. 现有手机协议兼容

现有 `agent.tasks.v1` 只接受 blocked/cloud_not_connected 和 cancelled/null，详情只有一条用户消息与本地行动。保持其四个命令和当前 UI 文案语义不变；不能直接给它加入 queued/running/completed 或助手回复。

手机接入批次增加独立在线能力 `agent.cloud.tasks.v1` 及原生持久映射，不把“已配置凭据”显示成在线成功。不复用现有取消行动固定 sequence=1 的写法存云行动，避免主键冲突。

任何页面刷新、进程重启、凭据配置成功、网络恢复或读取任务列表都不得自动上传历史本机任务。在线请求状态不明时先按持久云请求键查询；只有用户新建意图才能开启新的付费执行。

## 9. 预算与后续执行约束

M1C-2A 不派发模型，也不声称已经把新身份检查插进生产 Loop。M1C-2B 必须按以下顺序连接已有模块：

1. 认领成功，核对设备/任务权限和剩余截止时间。
2. 每一步先做持久派发门禁与预算预留，再次检查有效状态后才进入模型；设备/取消检查失败不使用缓存授权继续。
3. 已收到的有效 usage 仍幂等结算；不能因为设备撤销、任务取消或结果不再展示就丢弃账单。未知费用保留，不自动退款。
4. 每次模型返回后不再使用已撤回的摘要启动后续步骤；最终结果写入条件必须防止取消复活。
5. 模型派发与数据库不是原子操作。持久的预留/派发意图和晚到用量对账仍需恢复处理，不能靠进程内 Promise 存活保证收敛。本批基础库不会解除原有预算熔断。

全 App $2 上限仍未实现；手机直连 DeepSeek/Fish 在新账本范围之外。tokenizer、有效费率、认证、恢复/对账、远程 D1 或免费层验收缺一，不进入真实付费联调。

## 10. 验收矩阵

### M1C-2A 必须通过

- 新旧有效凭据映射同一 owner/预算；设备凭据不能伪造 owner、颁发新凭据或提升额度；数据库没有凭据原文。
- 畸形、未知、过期、撤销及查询故障均拒绝；凭据边界时刻和大小写规则有测试，错误不暴露 secret。
- 并发同键仅一条任务；同键异文冲突；不同 owner 隔离；同 owner 多设备共享活动任务限制；取消后重试不能复活。
- queued 只能认领一次；过期、错误执行权、别人的任务、撤销设备都不能认领或提交结果；并发取消与完成以条件更新结果为准。
- 数据库关闭/重开后恢复状态；处理中任务过原截止时间收敛，不重置时间、不自动产生新执行权。
- 结果可找回，确认必须幂等；24 小时后不可读取内容；指纹/正文清理后去重记录仍拒绝旧请求新执行。
- 非法最终结果、越界答复/行动、事务中途失败不会部分入账或改坏终态；迁移保留已有预算表数据。
- 本批类型、测试、格式、差异检查和独立只读复审通过。已有 86 项是前批基线，本批新增测试数以实际结果为准。

### 不在 M1C-2A 宣称通过

HTTPS 公网服务、私密管理 UI、Android Keystore/在线意图协议、即时跨实例中断供应商、Worker 生命周期内结算完成、云端物理清理定时器、精确 tokenizer、远程 D1/免费层、真实模型/手机联调。

## 11. 依据与设计检查

- [Cloudflare Web Crypto](https://developers.cloudflare.com/workers/runtime-apis/web-crypto/)：密码学随机源和 SHA-256 摘要支持。凭据生命周期和权限规则是本项目设计，不是平台自动提供的认证系统。
- [D1 Database](https://developers.cloudflare.com/d1/worker-api/d1-database/)：batch 的事务回滚语义；仍需实际 Workers/D1 验收。
- 本地依据：`agent-server/src/contracts.ts`、`src/loop.ts`、`src/budget.ts`；`AgentTaskService.kt` / `AgentTaskDao.kt` / `contracts/v1/README.md` 的本机 owner、唯一键及固定状态约束。

本轮已直接读取上述官方页面。设计自检覆盖：不混淆设备标识与硬件绑定、不混淆确认与查询、不混淆取消与退款、不混淆结果恢复与自动重跑、不混淆本机任务与云端执行。用户已经审阅确认，执行对应 M1C-2A 实施计划。

实施补充：截止判断使用 SQL 执行时钟与应用时间较晚者，返回前结合 SQL 读取时刻隐藏过期正文。复审发现的旧时间快照、SQL NULL 检查及测试毫秒格式问题均有失败复现和修复验证；共 118 项离线测试通过。数据库时间表达式依据 [SQLite 官方日期函数](https://www.sqlite.org/lang_datefunc.html) 的 `%s` 和 `%f`，已读取核对并做原生 SQLite 对照；不替代远程 D1 验收。完整交接见 [M1C-2A](../../handoffs/2026-09-15-agent-device-tasks.md)。
