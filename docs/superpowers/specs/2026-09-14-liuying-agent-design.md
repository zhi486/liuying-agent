# 流萤运动 Agent 设计

状态：用户已确认总体范围、隐私边界、权限与首页 C 布局；2026-09-14 落档。

## 产品目标

覆盖跑前计划、跑中陪伴、跑后复盘。首页采用 C「最近任务＋输入框」，底部为流萤、跑步、记录、设置。运动中进入其他页面仍可快速返回跑步。整体采用简洁留白、薄荷绿强调色、高对比文字与大触控区域。

## 实施边界

保留 Android 跑步协调器、手环连接、本地确定性规则、数据库、Fish 整句播报与内置流萤降级策略。云端处理有界 Agent 任务；手机掌管原始运动数据和健康警报。界面不得伪造在线、任务、数据或成功生成状态。

当前 Bridge 没有 Agent 任务和对话接口。第一批只交付首页与导航基础、统一视觉：最近任务真实为空，文字可编辑，发送明确标注尚未接入。不得宣称第一批已具备完整 Agent 能力。后续接口就绪后，任务与对话经原生持久化层读写，避免在 WebView 随意保存健康文本。

## 隐私与权限

GPS 轨迹、连续心率和手环原始流保留手机。云端只接收必要运动摘要、事件、偏好与经筛选的记忆。摘要仍属于敏感数据，不能等同匿名数据。默认不上传精确地点，不把密钥写进前端、日志、仓库或记忆。

Agent 可读取授权摘要、检索资料、提出计划和复盘，低风险偏好可记忆并可查看纠正。修改心率阈值、运动目标、跑步设置或删除记忆需确认。本地警报不可被 LLM 覆盖，Agent 不诊断疾病、不联系他人。

## 有界 Agent Loop

任务事件进入后先核对授权和预算，再组装最小上下文；模型选择白名单工具，执行后读取结构化结果，继续或结束。每次任务最多三次模型请求，工具参数必须验证，支持超时、取消、幂等和重复调用拦截。不给模型任意网络、文件或设置写权限。展示行动摘要、工具结果与来源，不展示模型内部思考。

跑中仍由本地事件触发：重要警报立即使用内置语音，常规陪伴异步准备，迟到内容丢弃。跑前和跑后可采用较宽时间预算。原始传感器逐点变化不触发模型请求。

## 长期记忆与双 RAG

记忆分为用户明确偏好、训练摘要、待确认候选。保存来源、时间、修订状态，支持查看、纠正、删除；推断不得当作用户确认事实。

Health RAG 使用官方运动健康来源与用户明确添加的资料；Firefly Lore RAG 使用《崩坏：星穹铁道》官方流萤角色、剧情、活动资料。分库检索，角色资料不参与健康判断。检索文档属于不可信数据，不得改变工具权限或系统规则。来源、发布时间、抓取时间、版本与撤回状态可追溯。官方资料按日增量检查，不能声称即时实时更新；获取失败显示上次成功时间。涉及剧情剧透需提供控制选项。

## 成本约束

免费层优先，目标每月总费用不超过 2 美元。金额须覆盖模型、Fish、嵌入、检索、存储和知识更新，不能仅计算跑中播报。发送请求前预留保守费用，事务处理并发扣额，结束后按实际用量结算，迟到请求仍计费。设置保守停止阈值与异常熔断，免费层耗尽停止相应云端任务，不自动升级套餐。软预算或告警不等于供应商硬限额；上线前核实各供应商能力和账单延迟，并留安全余量。

## 分阶段交付与验收

1. UI 基础：C 首页、四 Tab、活动跑步返回入口、统一主题。空状态真实，旧控制流程回归通过。
2. Agent 基础：任务存储、对话接口、白名单工具、有界循环、预算账本。验证取消、越权、重复调用、并发预算和离线。
3. 跑步周期：计划确认、事件陪伴、复盘追问。验证跨页面与锁屏保持运动、本地警报优先。
4. 记忆：来源、修订、候选确认与删除；验证隐私边界。
5. RAG：双库、引用、增量更新；验证错误来源、提示注入、过期资料和预算耗尽。
6. 户外验收：流量与 VPN、弱网、断网、锁屏、手环状态和预算耗尽场景。

首次 UI 交付不会自动安装手机或发布 GitHub；后续阶段各自细化接口与验收。
