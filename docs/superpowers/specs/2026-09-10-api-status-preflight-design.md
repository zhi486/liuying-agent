# 户外 API 状态与开跑前检测设计

日期：2026-09-10

状态：用户已确认聊天方案及本书面规格，并要求进入实施计划；尚未实施新功能。

代码基线：`bb461ea`。本文件描述拟实现行为，不表示当前手机已经具备这些功能。

## 1. 目标与已确认边界

用户不连接电脑、使用流量与 VPN 时，应能在跑步首页分清：文字大模型最近是否成功生成可用文字、Fish Audio 最近是否成功生成可用语音、实际播报来自哪里。

用户已依次确认：两个 API 独立展示最近真实结果与时间；开跑前手动检测；检测默认无声、试听单独点击；跑步中复用真实调用更新状态；网络或配置变化后提示复查；不持续发起付费探测。

成功只代表某次请求的结果，不保证下一次请求、整场跑步或耳机输出一定成功。VPN 图标、网页可访问、已填写 Key、历史缓存和内置流萤播放均不能替代 API 验证。

### 保持不变

- 固定健康提示原文、阈值及已打包的 14 条流萤音频不变，不重新生成资产。
- 在线仍将固定核心与可选陪伴句整段合成；公里数字整句合成，不恢复数字拼接。
- Fish 失败时固定事件播放内置流萤；公里语音跳过，距离、配速和记录不变。
- URGENT 立即本地，零文字 API、零 Fish；总语音关闭时仍保持静音。
- 不引入 Android 系统 TTS 回退，不改变音乐压低、焦点恢复和媒体取消规则。
- 正式语音的接纳起算 8／15 秒期限、可选文字生成最多 2 秒均不变。
- 不改 B5、GPS、千卡、运动记录结构，不处理尚未确定的 VPN 故障根因。

## 2. 方案选择

采用“原生维护真实请求状态＋首页展示＋跑前手动检测＋独立试听”。结果来自当前生产请求路径；首页不解析日志文件、不自行请求外部 API。

只提供被动状态虽然改动更小，但出门前可能一直未调用，不能满足主动检查需要。把检测与播放合并可以立即听到声音，但每次查询都会打断音乐。持续付费轮询会增加请求和耗电，且仍无法保证下一次成功，不采用。

## 3. 首页交互

在现有跑前准备区域加入紧凑的“云端服务”区域；运动中保留只读状态。原手环连接状态和原生服务连接状态保持独立，不能共用绿灯或文案。

| 信息 | 显示内容 | 成功的依据 |
| --- | --- | --- |
| 文字大模型 | 未启用、未配置、未检测、生成中、最近成功、失败或需复查；附结果时间 | 当次请求收到通过现有陪伴句校验的有效文字 |
| Fish Audio | 未配置、未检测、合成中、最近成功、失败或需复查；附结果时间 | 当次真实合成返回音频，且媒体准备成功 |
| 最近播报 | 在线流萤、内置流萤、公里语音已跳过；附播放状态和时间 | 实际语音路径的开始、结束或未播放结果 |

所有状态都有文字，不能仅依赖颜色。未检测为中性，进行中为等待状态，失败明确提示原因，需复查不显示成当前成功。成功文案必须带“最近”及时间，不写永久“已连接”。页面可刷新相对时间，但不由此发起网络调用。

结果区域保留最近成功时间；后续失败必须成为当前结果，不能被旧成功遮盖。没有实际播报时显示“尚未播报”。检测成功只更新 API 状态，不改写最近播报。

### 开跑前检测

- 按钮旁固定提示：“会使用少量 API 额度，不发声、不保存运动记录”。点击后仅发起这一轮，不自动重试。
- 每个可用服务最多一次应用层请求，独立执行、独立结束；其中一个失败不阻止另一个获得结果。
- 文字 AI 关闭时显示“未启用”且零请求；缺少相应配置时显示“未配置”且零请求。Fish 需要 Key 与声线配置完整。
- 总语音关闭不禁止用户明确点击的无声 Fish 检测，但标明“语音播报已关闭”并禁用试听，不自动打开语音。
- 仅在无活动或待恢复运动、会话为 `idle` 或 `finished`、原生恢复完成时允许。暂停运动仍算活动会话，不开放检测或试听。
- 前端防重复点击，原生也实行单轮互斥。重复命令或桥接重发不能产生第二批请求。
- 手动检测与试听共用跑前操作门；其间再次点击检测或试听均拒绝，不排队执行。
- 只允许 App 前台展示跑前页面期间检测或试听。离开该页面、应用进入后台、配置变化或开跑时取消并释放；恢复页面不自动重试或播放。

### 单独试听

- 仅使用本轮无声检测成功后保留的 Fish 音频，按钮注明“试听刚才生成的语音，不再调用 API”。不从旧播报缓存选取音频。
- 无有效检测音频时禁用并提示先检测；重启 App、开始新检测、网络或配置变化后旧试听资格失效。
- 用户点击才申请焦点并播放，遵守总语音开关、原助手音频路由和音乐压低／恢复规则。
- 试听失败单独显示“播放失败”；API 的成功结果仍保留，不能将耳机路由或焦点失败写成 Fish 网络失败。
- 试听属于预览，明确标注，不冒充正式健康事件、不走运动记录保存路径。

## 4. 请求及成功判定

### 文字大模型

复用 `AnthropicCompanionTextSource` 的当前配置、模型、请求构造、返回解析和陪伴句校验。手动检测使用已有跑步开始核心作为纯检测上下文，不发送用户运动数据、不创建会话，也不将生成文字排进 SpeechBus。

目前该类将网络、HTTP、解析和文字校验失败合并为 `null`。需在原因丢失前记录脱敏的结构化结果，继续保持调用方的可选后句语义。HTTP 成功但文字为空或不合要求时，显示“返回内容不可用”，不显示成功。

当前生产陪伴句来源为上述类。仓库保留的 `AnalysisManager` 与 `EmergencyPhraseCache` 在当前协调器只有取消／清理调用；本功能不启用旧分析、预生成或回填流程，不因新增状态增加这些付费调用。

### Fish Audio

复用 `OkHttpFishSynthesisClient`，明确 `readCache=false`。手动检测固定合成一句“开拓者，我在这里陪着你。”，不等待文字检测结果、不依赖 AI 输出。

使用独立播放器实例只做媒体准备，成功后释放该实例，不调用播放、不申请音频焦点。保留本轮音频文件供显式试听；试听时重新准备，文件消失或准备失败应明确报告，不能暗中重新合成。

HTTP 成功或非空文件本身不算完整 Fish 成功；需媒体准备成功。媒体准备失败归类为“音频准备失败”，与网络错误区分。准备成功之后的焦点拒绝、播放失败或耳机听不到仅属于播放状态。

检测文件放入 App 私有的独立预览目录，不覆盖正式缓存和内置资源。清理仅针对本功能拥有的临时文件，不接触已有测试音频、数据库或用户导出资料。

### 检测时限与成本

手动文字检测上限 2 秒，沿用陪伴句可用性要求；Fish 检测上限 15 秒，包含网络、下载和媒体准备。两项独立启动，分别从本轮接纳标记计算，使用现有包含休眠时间的单调时钟源。

Fish 检测通过不保证普通事件的 8 秒期限内也能完成。结果展示耗时，以便分清“能完成合成”与“足够及时”。

检测不排队、不循环、不做额外状态接口或缓存探测。检测调用使用不自动恢复失败连接或跟随重定向的请求配置；收到限流、鉴权或网络失败即结束，用户重试需再次点击。已经发往服务器的请求即使取消也可能计费，界面不承诺取消即免单。

## 5. 状态、失效和并发规则

新增原生 `CloudServiceStatusStore`，只负责内存状态，不保存 Key、声线值、请求正文或音频。每个服务独立维护配置可用性、在途操作、最近结果、最近成功时间及复查原因。

对外 `ServiceStatusSnapshot` 使用明确字段：`availability`（`disabled`／`missingConfiguration`／`ready`）、`inFlight`、`lastAttempt`、`lastSuccessAtMillis`、`staleReason`。`lastAttempt` 包含安全的来源（跑前检测／正式播报）、接纳／结束时间、耗时、结果（成功／失败／取消）与错误枚举。没有结果用 `null`，不以零时间冒充。

展示优先级为：未启用或未配置 → 请求中 → 需复查 → 最近结果 → 未检测。失效后的旧结果只能带“上次结果”说明；不得继续作为当前成功。进程重启清空这些短期状态，回到未检测，不增加数据库或长期监控历史。

状态更新带原生内部令牌：服务、配置代次、网络代次、操作序号。接纳请求时捕获代次，只有仍被认可的操作能写回结果；所有终态只接纳一次。并发时较旧请求即使更晚返回，也不能覆盖较新请求状态。

代次失效必须同时移除旧操作的在途显示，不能等一个不再被认可的回调来结束“请求中”。当前代次真实成功或失败后清除复查标记并展示新结果；取消不清除复查标记。播放状态同样按预览操作／正式语音会话校验身份，迟到的旧终态不得覆盖新播报。

- 对应 Key、文字模型、Fish 声线或启用设置改变时，使相关服务结果失效；无关主题设置不影响状态。
- 使用系统可观察的默认网络及相关能力变化作为失效通知；Wi-Fi／流量切换、网络丢失或可观察的 VPN 变化均提示复查。通知本身不发 API 请求。
- 重复的相同网络通知不反复使状态失效；首次建立监听基线不误报为用户切网。
- VPN 内部换节点未必产生系统通知，界面不承诺识别所有 VPN 变化；保留结果时间并允许用户手动重新检查。
- 系统报告联网、网络恢复都不能直接置成功；需当前代次的真实调用成功。
- 网络失效通知只更新可用性证据，不额外取消正式跑步语音；正式语音继续由既有期限和会话规则控制。旧网络代次的成功可以按原规则播放，但不能把新网络的 API 状态改成成功。
- 手动取消、开跑取消、页面离开、会话结束或高优先级抢占记录为取消，不伪造网络失败；只有本次请求确实触发自身时限才记录超时。
- 正式事件在开始请求前已耗尽排队预算时，不伪造 AI／Fish 请求失败；只记录本次语音未走在线路径。

## 6. 组件与接口边界

`CloudPreflightController` 负责跑前检测、预览文件、独立试听和取消。它调用现有文字／Fish 客户端及播放器工厂，不依赖运动传感器，不启动前台跑步服务。原生生命周期与开跑入口必须撤销跑前操作许可、取消网络和播放器，然后沿现有异步释放规则衔接，避免试听与开跑语音重叠。

`AppCoordinator` 订阅状态流并合并快照；配置接纳仍遵守现有 `settingsAcceptanceMutex` 和即时回调顺序，不引入第二个可能回滚设置的订阅。密钥留在原生私有设置，前端不直接访问网络或持有新增凭据副本。

`AppSnapshot` 新增 `cloudServices`（文字和 Fish 的独立快照、检测状态与试听资格）及 `voicePlayback`（来源、预览／正式用途、状态和时间）。语音来源由真实媒体启动、完成、失败及公里跳过路径产生；不能仅凭 Policy 选择、HTTP 成功或 `latestCoachMessage` 文本宣称已发声。

`VoicePolicyTtsEngine` 与文字／Fish 请求路径增加小范围状态报告，不重写 `PreparedVoicePlayer` 的线程、取消、焦点和清理机制。媒体成功准备、实际启动、终态分别报告；播放信息只证明播放器行为，不自动确认耳机听感。

桥接新增 `services.check`、`services.preview`、`services.cancel` 三个空请求体命令。接纳立即返回结果，长请求结果通过快照推送；不阻塞桥接等候网络完成。沿用现有来源限制、命令 ID 去重和错误码；运动中拒绝使用 `COMMAND_NOT_ALLOWED`，无试听资源使用 `RESOURCE_UNAVAILABLE`。

新增能力标记 `services.v1`，与现有能力并列；原生序列化、`BridgeCodec`、前端类型／Zod、契约文档及 fixtures 同步更新。保留已有消息封装版本；本地前端和原生同包升级，不增加跨版本远程兼容层。缺少新能力时前端隐藏入口，不允许浏览器 mock 发起真实请求。

主要受影响位置：

- 新增云端状态与跑前控制器所在的原生小模块，以及对应纯状态／取消测试。
- `ai/AnthropicCompanionTextSource.kt`、`speech/OkHttpFishSynthesisClient.kt`、`speech/VoicePolicyTtsEngine.kt` 与最小媒体生命周期报告点。
- `di/AppModule.kt`、`coordinator/AppCoordinator.kt`、`coordinator/AppSnapshot.kt`、`ui/web/NativeWebBridge.kt` 和桥接契约。
- `frontend/src/features/running/RunningPage.tsx`、前端桥接类型／校验、mock 快照及对应测试。

原生安全页无需复制检测操作；已有安全页和设置页功能必须保持可用。不顺带整理旧分析类或重构无关 UI。

## 7. 错误与隐私

错误由原生映射为有限枚举和固定中文说明：鉴权／访问被拒、请求受限、服务端错误、网络错误、超时、返回内容不可用、音频准备失败、播放失败。不能仅凭 401／403 断言 Key 过期，也不能仅凭 429 断言余额不足；只有安全且明确的证据才使用更具体说明。

原始响应体、异常消息、请求头、Key、声线配置值、IP、VPN 节点和路线均不进入新增快照、前端提示或诊断。允许有限状态类别及安全耗时／时间，不保存新的原始请求日志。取消原因和 API 失败原因分开。

## 8. 验收标准

| 场景 | 必须验证的结果 |
| --- | --- |
| 两项配置有效且模拟成功 | 各一次请求，独立时间／耗时，Fish 完成媒体准备，无音频焦点、零播放 |
| 文字 AI 关闭或配置缺失 | 对应零请求，准确显示未启用／未配置，另一服务不受影响 |
| 一成功一失败 | 两项各自结果，无“全部在线”推断，既有语音降级策略不变 |
| HTTP 成功但无可用文字／坏音频 | 返回内容或媒体错误，不误报成功 |
| 检测超时及迟到返回 | 按接纳起算到期、取消底层工作，迟到结果不回绿、不产生试听资格 |
| 重复点击及桥接重发 | 同轮最多各一次，不排队，不自动重试 |
| 切网、改 Key／声线、旧请求后到 | 正确提示复查，旧代次不得覆盖新结果，无凭据值出现在快照 |
| 开跑、暂停中点击、后台或离页 | 原生拒绝或取消跑前操作，不保存测试运动、不与健康播报争抢 |
| 独立试听 | 只播当轮生成文件，零新 API 请求；关闭语音或文件失效时不自动补请求 |
| 音频焦点／播放失败 | 播放状态单独失败，先前真实 API 结果不被改成网络失败 |
| 内置、URGENT 与公里离线跳过 | 来源和原因正确；不伪造 API 请求或成功，不引入系统 TTS |
| 进程重启与时间变化 | 不恢复虚假在线状态；期限使用单调时钟，显示时间不产生负耗时 |
| 正式语音回归 | 8／15 秒含排队、文字 2 秒、取消后不迟到补播、焦点释放规则仍通过 |
| 桥接与前端回归 | 新合法 fixtures 两端通过，非法字段／来源被拒；旧跑步、手环与设置测试不退化 |

先进行不联网的 JVM、契约、前端、模拟网络及无声设备测试。正式构建仍需沿用原签名、检查 APK 不含凭据、保护原记录和设置。

真实流量＋VPN 两 API 检测、Beats 实听和 QQ 音乐压低恢复属于后续人工验收：开始前明确请求次数、成本和用户准备状态。当前设计批准不授权此刻自动调用付费 API。室内通过也不能替代后续锁屏、户外和 B5 射频验收。
