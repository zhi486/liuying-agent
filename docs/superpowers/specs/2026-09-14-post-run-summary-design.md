# 无广告跑后总结页设计

## 已确认需求

参考用户提供的 Keep 总结页信息层级，使用流萤现有薄荷绿视觉体系，不复制广告、会员引导、装备推广、社区发布或互动模块。用户已确认先做真实总结、分段与曲线，再接地图和 AI 复盘。

## 数据核查

- `RunSessionEntity` 已保存距离、用时、平均配速、平均心率、平均步频和起止时间。
- `SplitEntity` 已保存每公里距离、时长、平均配速、平均心率及平均步频。
- `RoutePointEntity` 已保存带时间戳与精度的 GPS 点，但没有暂停分段标识。
- 数据库没有连续心率、实时配速或暂停事件序列。旧记录无法恢复这些曲线，不使用插值伪装真实采样。
- 当前前端仅有 `history.query` 分页列表；总结页需要独立只读详情命令。

## 第一批：离线可用的真实总结

新增 `/history/:sessionId`，从记录列表进入。跑步结束且本地保存成功后提供「查看本次总结」入口，不在保存完成前跳转。返回记录列表不影响活动跑步状态。

页面依次显示日期与跑步类型、主要距离、用时/平均配速/平均心率/平均步频、每公里分段表、分段配速柱状图、事实摘要。图明确标注「每公里平均配速」，不称为实时配速曲线。心率缺失显示「未采集」，分段为空显示「未保存分段数据」，不制造末段。

不展示千卡、最大摄氧量、训练负荷、训练效果分数。没有可靠计算来源前，不用公式猜测。

新增 `history.detail` 请求 `{ sessionId: string }`，仅查询已完成且保存的记录，返回概要和分段，不返回 GPS。非法参数、记录不存在、非完成记录、存储失败明确区分。前端校验返回记录 ID 与请求一致，切换记录时丢弃迟到响应。旧版原生不支持详情时显示升级提示，不导致整个记录页失效。

## 第二批：连续数据采样与曲线

另行细化 Room 迁移、采样频率和保留上限后实施。保存活动用时、心率、配速、数据质量与暂停/恢复分界。断联、陈旧样本和暂停形成断点，不画成零心率或跨缺口直线；历史记录显示「本次未保存连续数据」。保持现有健康判断和语音触发独立，不增加云端请求。

## 第三批：路线与 AI 复盘

路线默认本地读取；先确定地图供应商、隐私与预算，再决定是否请求底图。GPS 断段不能任意连接。无轨迹明确显示无记录，不展示模拟路线。

事实摘要先本地可用。AI 复盘沿用已确认 Agent 隐私与预算边界，仅传必要摘要，不自动上传位置或连续心率。在线复盘失败不阻塞记录；不凭空提供健康诊断。

## 验收

- 原生详情查询：真实概要/分段、空分段、空心率、非法 ID、不存在、非完成记录和读取失败。
- 前端：加载、详情、错误重试、旧版兼容、切换记录的迟到响应、返回导航、保存前禁用总结入口。
- 图表：由原始分段值生成、缺失值不归零、有文字/表格等价内容。
- 320px/360px/390px、浅色/深色、长用时、多分段；可滚动查看全部内容且底部导航不遮挡末尾。
- 现有跑步控制、手环预连接、结束确认、语音、记录分页和设置测试保持通过。
- 真机确认一次已有记录和一次新完成跑步；未安装不声称验收。

## 修改边界

优先扩展 `BridgeCodec.kt`、`NativeWebBridge.kt`、`AppCoordinator.kt` 和现有记录仓储查询，不重构跑步协调器。前端修改 `contract.ts`、`schemas.ts`、路由及记录入口；详情请求、图表、页面分别放在 `features/history/`。第一批不迁移数据库、不引入地图或图表依赖、不自动提交和安装。
