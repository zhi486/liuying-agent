## 文件与机制

- `agent-server/src/maintenance.ts`：先调用既有 `purge()`，再读持久游标、调用一页 `recoverFreeExecutions()`，成功后版本条件更新游标。失败为静态 `maintenance_unavailable`；版本竞争失败返回 `cursorSaved=false`，不覆盖更新者。
- `migrations/0004_agent_maintenance.sql`：增量添加 `agent_maintenance_state`，不修改旧任务或账本；重复应用不重置游标。正式 D1 部署前必须先应用该迁移，本轮只在本地测试。
- `src/worker.ts`：新增 `scheduled`，完整 await 维护；不依赖 DeepSeek 密钥或当前费率，不增加公开管理路由。
- `wrangler.jsonc`：明确空 Cron 数组；六个普通 HTTP 路由和既有 DO 不变。
- `test/sqlite-d1.ts`：本地真实 SQLite 加载新迁移；新增 `test/maintenance.test.ts`、`runtime-test/maintenance.spec.mjs`。

维护只清空过期结果/指纹、收敛超时和恢复账务，不删除任务墓碑、账户、设备或预算记录。处理旧收据使用原预留费率，当前配置过期不阻碍结算。

## 仍未覆盖

46 是查询条数，不是扫描行数、CPU、费用或物理清除时延保证。`purge()` 仍为既有全表条件 UPDATE，云 Cron 启用前需独立测 CPU/D1 读写与数据规模；不得套用前一批入口最大 7 ms 的结论。没有配置 Cron 或外部告警，静态失败事件不是已上线的通知系统。

手机仍只有本机任务，真实云端 Agent 尚不可用。用户需填的新密钥、人工核验费率、设备凭据发放及获准部署均未执行；没有自动刷新价格或延长 24 小时保护。自动更新报价需要另做来源与变更审核，不能只更新旧价格的时间戳。
