## 最小采集步骤

1. 用户明确同意短期开启 HCI 日志及必要的蓝牙重启。若必须导出 bugreport，另外说明其可能包含非 B5 的系统日志、设备与应用信息，并获得同意；原始包仅留本地，不上传，不将全文载入模型。

3. 官方 Keep 连接同一 B5，核对运动类型和 B5 屏幕。先不自动开始或替用户保存/删除 Keep 记录。
4. 用户开始约 2–3 分钟对照运动，记录开始、数值变化、暂停、恢复、结束的时间点与屏幕数值/单位。至少覆盖静止、慢走、快走和短暂停；每个操作之间保留稳定观察窗口。
5. 室内没有可靠 GPS 时，距离与配速可能不变。此时只验证实际发生变化的字段；不把室内抖动或全部为 0 的样本当作单位证明，不切换运动类型后假定编码相同。
6. 结束运动后再封口日志，避免重现旧包漏掉 STOP 的问题；恢复采集前的日志设置并核对。不要清除历史 HCI 或用户运动数据。
7. 若需 bugreport，仅列出压缩包中蓝牙日志条目并提取目标时间窗口的 HCI 文件；不展开/输出系统报告全文。原始证据放在被 Git 忽略的 build 目录，应用诊断中禁止加入原始 HCI、设备地址或凭据。

## 分析与实现门槛

- 复用 btsnoop → ATT → B3 重组与 CRC 校验，按目标连接、时间窗口、SID 0x0e / CID 0x06 筛选；连接 handle 每次重新识别，不沿用旧值。
- 对 repeated DisplayData 的 dataType/dataValue 做时间对齐，每个待实现字段至少取得多个不同的非零值和对应屏幕单位；单个样本不定映射。
- 明确取整、缩放、暂停、缺失数据和无 GPS 时的行为。只有已证明的字段才进入生产编码，未确认字段保持现有安全行为。
- 千卡协议映射不代表已有可信千卡来源；当前 App 缺少经用户确认的体重和计算模型，不能凭空生成真实消耗值。
- 先补离线 fixture 与编码测试，再扩展下行接口，执行回归、构建和真机双屏对照；不把发送成功当作屏幕显示正确。
