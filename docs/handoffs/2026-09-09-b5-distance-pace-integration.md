## 本轮实现

- `AppCoordinator` 在会话代次与 RUNNING 状态检查后，将与 UI 同源、经过累计距离重基准处理的指标下发；定位陈旧时配速传 null。进程恢复挂接和暂停恢复先传累计距离与空配速。
- `RunLifecycleAwareSensor.onRunMetricsUpdated` 经 `CompositeSensorDataSource` 仅透传至手环，不反向修改手机 GPS。
- `KeepB5DisplayMetrics` 使用整数米和秒/公里；距离截取整数米，配速按当前 Web UI 四舍五入到整秒。负数、非有限数和 int32 越界值归为无效零值，不溢出。
- B5 监督器保存最新指标，在现有串行写入锁内解析提交时取当前快照；暂停冻结距离并清空配速，恢复等待新配速，断线重连保留累计距离，新跑及停止清空指标。既有 epoch/GATT/lifecycle 守卫继续拒绝旧会话批次。
- 修复相关停止边界：手动断开后再停止，即使已无 GATT 资源，也先切换到 STOPPED；避免迟到指标在已结束会话仍被接收。
- 参数沿 BleTransport → GATT binding → Android GATT session → B3 编码器传递。DisplayData type2 为距离米、type3 为秒/公里，0 按本轮官方样本表示无有效配速。
- type1 千卡沿用原缺省零占位，未添加估算模型或虚构数据来源。这个占位不代表真实消耗为零。
- 本轮不改原有首次 4.5 秒、后续每秒同步及 6 秒心跳节奏；不改原暂停保活协议，也没有接入新 STOP 报文。
